VS Code とは

Visual Studio Code（略称 VS Code）は、Microsoft が無料で配布しているコードエディタです。2015年に公開され、現在は世界で最も使われている開発用エディタです。

  • 無料・オープンソース（本体は MIT ライセンス）。Mac / Windows / Linux で同じように使える
  • マウスでもキーボードでも操作できる GUI アプリ。インストールしたその日から使える
  • 拡張機能で、言語対応・デバッグ・Git・AI補完などを後から足せる
  • ターミナル内蔵。エディタを離れずにコマンドを実行できる
  • リモート開発。SSH 先のサーバーや Docker コンテナの中のファイルを、手元と同じ感覚で編集できる

「メモ帳より高機能で、統合開発環境（IDE）より軽い」という立ち位置です。

課題を GitHub に上げる手順は「Git / GitHub と接続して課題を上げる（03-18）」へ。

Vim との違い

いちばん大きい違いは、Vim は「モードを切り替えてキーボードだけで操る」、VS Code は「誰でもすぐ使えて、機能は拡張で足す」 という設計の違いです。どちらが優れているというより得意な場面が違い、VS Code に Vim の操作方法を入れて両方をいいとこ取りする人も多いです。

比較項目VimVS Code
動く場所ターミナルの中（CUI）ウィンドウアプリ（GUI）
操作ノーマル・挿入・ビジュアルなどモードを切り替える。マウスはほぼ使わない普通のアプリと同じ。マウスとショートカットの両方
覚える量多い（:wq で終了、dd で行削除など）少ない。メニューから機能を探せる
起動の速さ・軽さ非常に軽い。数MBのメモリで動く重め（Electron 製で数百MB使うことも）
サーバーでの使用ほぼ全ての Linux に最初から入っている（vi）普通は入っていない。Remote-SSH で手元から接続する
コード補完・エラー表示プラグインと設定で自分で組む最初から入っている（拡張を入れるだけ）
拡張の追加設定ファイル .vimrc やプラグインマネージャーで管理画面から検索して「インストール」を押すだけ
デバッグ別ツールを使うことが多いブレークポイントを置いて画面上で実行を止められる
Gitコマンドやプラグインで操作差分表示・コミットが画面からできる
AI 支援プラグインで対応GitHub Copilot などが標準的に統合されている

使い分けの目安

  • Vim が向く ― SSH で入ったサーバーで設定ファイルを少し直す、キーボードだけで高速に書きたい
  • VS Code が向く ― プロジェクト全体を開いて開発する、初心者が学ぶ、デバッグや Git を画面で見たい
  • Vim に慣れている人 ― VS Code に拡張「Vim」を入れれば、いつもの hjkl や dd がそのまま使える（下のセットアップ参照）

インストール手順

どのOSでも、公式サイト code.visualstudio.com から無料でダウンロードできます。所要時間は5〜10分です。

この授業の皆さんは Ubuntu を使っているので、.deb をダウンロードしてください。すぐ下の「Linux（Ubuntu / Debian）」の手順で進めます。

似た名前の「Visual Studio」は別の重い開発ツールなので間違えないように。

Linux（Ubuntu / Debian）← 授業ではこれ

皆さんは Ubuntu なので、.deb を選んでダウンロードしてください（.rpm ではありません）。

  1. 公式サイトのダウンロードページで、Linux の .deb（Debian, Ubuntu）のボタンを押す
  2. ターミナルを開き、ダウンロードフォルダに移動してインストール（Microsoft のリポジトリも自動で登録され、以降は apt で更新される） 
    cd ~/Downloads
sudo apt install ./code_*.deb
    ※ 日本語環境ではフォルダ名が ~/ダウンロード の場合があります。パスワードを聞かれたら、ログイン時のパスワードを入力（画面には表示されません）。
  3. アプリ一覧の「Visual Studio Code」か、ターミナルで code と打って起動

ターミナルで code と打つと VS Code が開きます。
code . なら「今いるフォルダ」を、code index.html ならそのファイルを開きます。Vim で vim index.html と打っていたのと同じ感覚で使えます。

code            # VS Code を起動する
code .          # 今いるフォルダを VS Code で開く（いちばんよく使う）
code index.html # ファイルを指定して開く

補足：.deb と .rpm の違い

どちらも Linux 用の「インストール用パッケージ」ですが、Linux の系統（ディストリビューション）ごとに形式が違います。自分の OS に合わない方を選ぶとインストールできません。

.deb.rpm
対応する OSUbuntu、Debian、Linux Mint など（Debian 系）Fedora、Red Hat、CentOS、Rocky Linux など（Red Hat 系）
インストールするコマンドapt（dpkg）dnf / yum（rpm）
名前の由来Debian の略Red Hat Package Manager の略

Windows の .exe、Mac の .dmg のように、Linux では系統によって .deb と .rpm を使い分ける、と覚えておけば十分です。自分の OS が分からない時は、ターミナルで cat /etc/os-release を実行すると表示されます。

その他の方法（Snap など）は公式の Linux 向け手順を参照。

参考：自宅の Mac で使う場合

  1. 公式サイトで「Download for macOS」を押す（Apple シリコン / Intel 両対応の Universal 版でOK）
  2. ダウンロードされた zip を開くと「Visual Studio Code.app」が出てくる
  3. そのアプリを 「アプリケーション」フォルダに移動する（ダウンロードフォルダのままだと自動更新が効かない）
  4. ダブルクリックで起動。「インターネットからダウンロードされたアプリです」と出たら「開く」

Homebrew を使っているなら、ターミナルで次の1行でも入ります。

brew install --cask visual-studio-code

参考：自宅の Windows で使う場合

  1. 公式サイトで「Download for Windows」を押す（User Installer でOK。管理者権限が不要）
  2. ダウンロードした VSCodeUserSetup-xxx.exe を実行
  3. 使用許諾契約に同意 → 次へ
  4. 「追加タスクの選択」で次の2つにチェック（後から便利）
    • 「Code で開く」アクションをエクスプローラーのファイル・ディレクトリのコンテキストメニューに追加する
    • PATH への追加（通常はオンになっている）
  5. 「インストール」→「完了」で起動

初期セットアップ

この章で必ずやるのは「1. VS Code と GitHub を連携する」だけです。2 から先は「やっておくと便利」な設定集なので、余裕がある人だけどうぞ（あわせて Git の章の 名前とメールの登録（STEP 4）と GitHub へのログイン（STEP 5）も必ずやります）。

1. VS Code と GitHub を連携する（必ずやる）

VS Code を入れて最初に起動すると、GitHub アカウントでサインインする案内が出てきます。これは授業で必ずやってください。数分で終わります。

  1. VS Code を起動する
  2. 次のどちらかからサインインを始める
    • 起動直後のウェルカム画面に出る「Sign in（サインイン）」のボタン
    • 出てこなかった・閉じてしまった時は、左下の人の形のアイコン（アカウント）→「GitHub でサインイン」（Sign in with GitHub）
  3. ブラウザが開くので、GitHub にログインして Authorize（許可）を押す
  4. 「Visual Studio Code を開きますか？」と聞かれたら 開く を押して VS Code に戻る
  5. VS Code に「拡張機能 'GitHub' がサインインしようとしています」などと出たら 許可
  6. 左下のアカウントアイコンを押して、自分の GitHub ユーザー名が表示されていれば完了

これをやっておくと、

  • VS Code のソース管理のボタン（同期・プッシュ）から、パスワードを聞かれずに GitHub へアップロードできる
  • VS Code のターミナルで git push した時も、VS Code がログインを肩代わりしてくれる
  • GitHub Copilot（AI の補完）や、設定の同期も同じアカウントで使える

2. 日本語化（任意）

やってもやらなくてもOKです。英語のメニューのまま使うのもおすすめです。

  • 英語のままのメリット：Git、GitHub、ターミナル、エラーメッセージなど、開発で使うツールはほとんどが英語。VS Code で File / Terminal / Source Control などの英語に慣れておくと、他のツールを使う時やネットで調べる時に困らない（検索で出てくる解説も英語メニュー前提のものが多い）
  • 日本語にするメリット：最初のうちは迷わずに操作できる。慣れてきたら英語に戻すこともできる

日本語にしたい人は次の手順で設定します。

  1. 左端のアイコン列から 拡張機能（四角が4つのアイコン、Cmd+Shift+X / Ctrl+Shift+X）を開く
  2. Japanese Language Pack を検索し、Microsoft 製のものを「Install」
  3. 右下に出る「Change Language and Restart」を押すと、再起動後に日本語になる

英語に戻したくなったら、コマンドパレット（Ctrl+Shift+P）で Configure Display Language → en を選んで再起動します。

設定画面は Cmd+,（Windows/Linux は Ctrl+,）。上の検索欄に設定名を入れて変更します。

5. ターミナルから code で開く（Ubuntu は設定不要）

Vim で vim index.html と打っていた感覚で、code .（今いるフォルダを開く）や code index.html が使えるようになります。

  • Mac ― Cmd+Shift+P でコマンドパレットを開き、Shell Command: Install 'code' command in PATH を実行
  • Windows / Linux ― インストール時に自動で使えるようになる（使えない時はターミナルを開き直す）

6. Vim から移る人向け：Vim キーバインド

  1. 拡張機能で Vim（vscodevim）をインストール
  2. これだけでノーマル/挿入/ビジュアルモード、:w :q、dd yy p などが使える
  3. Mac のみ：j を押しっぱなしにしても連続で動かない時は、ターミナルで次を実行して VS Code を再起動 
    defaults write com.microsoft.VSCode ApplePressAndHoldEnabled -bool false
  4. Ctrl+C や Ctrl+V を VS Code 側（コピー・貼り付け）に残したい場合は、設定の Vim: Handle Keys で個別に切り替えられる

Git / GitHub と接続して課題を上げる（03-18）

VS Code で作った課題を GitHub にアップロードし、GitHub Pages で公開するまでの手順です。例として、教科書の練習問題 03-18（お問い合わせフォーム）を上げます。

この章は Vagrant（仮想マシン）を起動せずに進めてください。
皆さんの PC はそのまま Ubuntu なので、Vagrant を起動しなくても VS Code もブラウザも他のアプリも使えます。Vagrant を通しても通さなくても課題は上げられますが、まずは Vagrant を使わない方法を説明します。いつも Vagrant の中で作業している人向けのやり方は、この章の後の「Vagrant（仮想マシン）からやる場合」にまとめてあります。

まず全体像：自分のPCと GitHub の関係

ファイルは 自分のPCの中で2段階セーブ（git add → git commit）してから、git push で GitHub に送ります。ゲームにたとえると、PC の中のセーブが「本体セーブ」、GitHub が「クラウドセーブ」です。

  • git add作業フォルダ → ステージへ（セーブ候補に入れる）
  • git commitステージ → ローカルリポジトリへ（PC の中にセーブ）
  • git pushPC → GitHub へ送る
  • git pullGitHub → PC へ取り込む
  • git remote -v送り先（リモート）の URL を確認
  • git status今どこに何があるかを確認

⚠ commit しただけでは GitHub には届きません（まだ自分のPCの中にあるだけ）。GitHub に反映させるには必ず git push まで実行します。push すると、GitHub Pages の公開サイトも数分で自動更新されます。

リポジトリは章ごとに1つ（ch03）、課題はフォルダで分ける（03-18、03-19 …）、ブランチは main だけ、というルールで進めます。
以下の h-kondo は例です。自分の GitHub ユーザー名に読み替えてください。

ch03/                 ← GitHub のリポジトリ1つぶん
├── index.html        ← 課題へのリンク集（トップページ）
├── 03-18/            ← 1つ目の課題（今回）
│   ├── index.html
│   └── style.css
└── 03-19/            ← 2つ目の課題（次回はここに足していく）
    ├── index.html
    └── style.css

課題が増えてもリポジトリは ch03 の1つのままで、その中に 03-19、03-20 …とフォルダを足していくだけです。どの課題フォルダにも、同じ名前の index.html と style.css を入れます（フォルダが分かれているので、同じ名前でもぶつかりません）。

課題手元のフォルダ公開される URL（GitHub Pages）
03-18ch03/03-18/https://h-kondo.github.io/ch03/03-18/
03-19ch03/03-19/https://h-kondo.github.io/ch03/03-19/

STEP 1. ch03 フォルダを作って VS Code で開く

今まで使っていた Vagrant のフォルダとは別の、独立した場所に新しくフォルダを作ってください。
新しく作ったフォルダを、新しく Git（GitHub）と接続するためです。Vagrant のフォルダの中に作ったり、今までの課題のフォルダを使い回したりすると、Git の管理がほかのファイルと混ざってしまいます。下のコマンドどおり、ホームフォルダの直下（~/ch03）に作れば大丈夫です。
※ どうしても Vagrant の中から作業したい人だけは、後の「Vagrant（仮想マシン）からやる場合」の置き場所に従ってください。

mkdir -p ~/ch03/03-18   # ch03 と、その中の 03-18 をまとめて作る
cd ~/ch03
code .                  # ch03 フォルダを VS Code で開く

⚠ VS Code では課題のフォルダ（03-18）ではなく、ch03 フォルダを開くのがポイントです。Git はリポジトリ（ch03）単位で管理するためです。

STEP 2. 03-18 の HTML と CSS を書く

左のエクスプローラーで 03-18 フォルダを右クリック →「新しいファイル」で、index.html と style.css を作ります。⚠ ファイル名はすべて小文字（Index.html だと Pages で開けません）。

03-18/index.html 
<!DOCTYPE html>
<html lang="ja">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>お問い合わせ</title>
    <link rel="stylesheet" href="style.css">
</head>
<body>
    <h1>お問い合わせ</h1>
    <p>ご質問がありましたらお気軽にご連絡ください。</p>
    <p>お名前</p>
    <input type="text" placeholder="例：大本真奈美">
    <p>ご質問内容</p>
    <select name="question">
        <option value="a">商品の質問</option>
        <option value="b">お店について</option>
        <option value="c">その他</option>
    </select>
    <p>ご意見・ご質問</p>
    <textarea name="message"></textarea>
</body>
</html>

⚠ <link rel="stylesheet" href="style.css"> を <head> の中に入れないと、CSS を別ファイルに分けたときに反映されません。href の名前と CSS のファイル名（style.css）が1文字も違わないことも確認しましょう。

03-18/style.css 
/* 入力フィールド共通の装飾 */
input[type="text"],
select,
textarea {
    width: 100%;             /* 横幅いっぱいに広げる */
    padding: 12px;           /* 内側に余白を作ってクリックしやすく */
    border: 1px solid #ccc;  /* 消えた枠線を復活させる */
    border-radius: 6px;      /* 角を丸くして柔らかい印象に */
    margin-bottom: 25px;     /* 次の項目との間に余白を作る */
    font-size: 16px;         /* 入力する文字の大きさ */
}

/* テキストエリアの高さ指定 */
textarea {
    height: 150px;           /* 高さを固定して入力しやすくする */
}

まずはローカル（自分のPC）で表示を確認する

GitHub に上げる前に、自分のPCのブラウザできちんと表示されるかを必ず確認します。ここで崩れているものは、GitHub に上げても崩れたままです。

VS Code のターミナルで 03-18 フォルダに移動して、ブラウザで開きます。

cd ~/ch03/03-18
open index.html     # ブラウザ（Chrome など）で開く

※ ファイルマネージャーで index.html をダブルクリックしても開けます。

確認するポイント：

  • 見出し・入力欄・選択肢・テキストエリアがすべて表示されているか
  • CSS が効いているか（入力欄が横いっぱいに広がり、角が丸くなっているか）。効いていなければ <link rel="stylesheet" href="style.css"> とファイル名を確認
  • 文字化けしていないか（していれば <meta charset="UTF-8"> があるか確認）

ファイルを直したらブラウザを再読み込み（F5）して確認します。拡張機能「Live Server」を入れている人は、index.html を右クリック →「Open with Live Server」で開くと、保存するたびに自動で再読み込みされて便利です。

トップページ（リンク集）も作る

ch03 の直下（03-18 フォルダの外）に index.html を作ります。課題が増えたら <li> を1行ずつ足します。

ch03/index.html 
<!DOCTYPE html>
<html lang="ja">
<head>
    <meta charset="UTF-8">
    <title>ch03 課題一覧</title>
</head>
<body>
    <h1>ch03 課題一覧</h1>
    <ul>
        <li><a href="03-18/">03-18 お問い合わせ</a></li>
    </ul>
</body>
</html>

STEP 3. Git が入っているか確認する

VS Code のターミナル（Ctrl+@）で実行します。

git --version

git version 2.xx.x と出ればOK。出なければインストールします。

sudo apt update
sudo apt install -y git

STEP 4. 名前とメールアドレスを登録する（最初に1回だけ）

コミット（セーブ）に「誰が変更したか」として記録されます。GitHub のユーザー名と、GitHub に登録したメールアドレスを使います。

git config --global user.name "h-kondo"
git config --global user.email "GitHubに登録したメールアドレス"

登録できたか確認します。

git config --global --list

次のように出れば成功です（q で閉じる）。

user.name=h-kondo
user.email=xxxxx@gmail.com
  • --global を付けると、そのPCのすべてのリポジトリに設定されます
  • メールアドレスを公開したくない人は、GitHub の Settings → Emails にある 数字+ユーザー名@users.noreply.github.com を使えます
よくある間違い出るエラー正しい書き方
名前とメールを登録していないPlease tell me who you are / unable to auto-detect email address上の2行を実行する
user.name を書き忘れた
git config --global h-kondo		error: key does not contain a section: h-kondogit config --global user.name "h-kondo"

STEP 5. GitHub と接続する（ログイン・最初に1回だけ）

VS Code をインストールした後に「初期セットアップ 1. VS Code と GitHub を連携する」をすでにやっている人は、この STEP は不要です。STEP 6 へ進んでください。
※ その場合も、STEP 7 で git push した時にユーザー名やパスワードを聞かれたら、この STEP をやってください（VS Code の外のターミナルから push する時などは、こちらのログインが必要になります）。

⚠ GitHub はパスワードでのアップロードを受け付けません。GitHub CLI（gh）でログインします。

sudo apt install -y gh
gh auth login
質問選ぶもの
Where do you use GitHub?GitHub.com
What is your preferred protocol?HTTPS
Authenticate Git with your GitHub credentials?Yes
How would you like to authenticate?Login with a web browser

画面に出た 8桁のコードをコピー → ブラウザで GitHub にログインしてコードを入力 → Authorize。

gh auth status

Logged in to github.com account h-kondo と出ればOK。

Vagrant（仮想マシン）からやる場合

これは、皆さんがこれまで行ってきた方法です。
今までは Vagrant の中で Vim を使って書き、そのまま GitHub に push していたと思います。ここでは改めて、「自分は今どのコンピューターの、どのフォルダで Git を動かしているのか」という仕組みを理解し、Vagrant あり・なしのどちらでも自由に扱えるように手順をまとめます。
Vagrant の中から GitHub に上げる場合も、なんとなくコマンドを打つのではなく、状況と仕組みを理解したうえで行うようにしてください。

仕組み：Vagrant のフォルダは PC と仮想マシンで共有されている

Vagrantfile がある PC 側のフォルダは、仮想マシンの中では /vagrant として見えます。どちらで書き換えても、同じファイルが変わります。

PC（Ubuntu）側                   仮想マシンの中
~/vagrant/            ⇔  共有  ⇔  /vagrant/
└── ch03/                          └── ch03/
    └── 03-18/                         └── 03-18/

※ ~/vagrant は例です。自分の Vagrantfile がある場所に読み替えてください。

やり方1：共有フォルダを PC 側の VS Code で開く（おすすめ）

ファイルは共有フォルダに置き、編集も Git も PC 側の VS Code でやる方法です。手順は「Vagrant を使わない方法」とまったく同じで、ch03 を作る場所が違うだけです。

cd ~/vagrant              # Vagrantfile がある場所
mkdir -p ch03/03-18
cd ch03
code .

⚠ Vagrant のフォルダ（例：webex1）がすでに Git につながっている場合、この方法は使えません。先に「親のフォルダがすでに Git につながっていると失敗する」の確認をしてください。

あとは STEP 2〜9 と同じです（名前の登録・GitHub へのログインも PC 側で1回やれば OK）。仮想マシンの中からも /vagrant/ch03 で同じファイルが見えます。

やり方2：仮想マシンの中で Git を使う

いつもどおり仮想マシンに入って、Vim で書き、Git も仮想マシンの中で実行する方法です。

vagrant up                # 仮想マシンを起動
vagrant ssh               # 仮想マシンに入る
cd /vagrant/ch03          # 共有フォルダの ch03 に移動

仮想マシンは PC とは別のコンピューター（PC の中で起動している、もう1台の別の PC という扱い）なので、Git の準備をもう一度やり直す必要があります。PC 側で登録した名前やログインは、仮想マシンの中には引き継がれません。

  1. Git の確認とインストール（STEP 3）：git --version
  2. 名前とメールの登録（STEP 4）：git config --global user.name "h-kondo" など
  3. GitHub へのログイン（STEP 5）：sudo apt install -y gh → gh auth login
    仮想マシンにはブラウザが無いので、「Login with a web browser」を選んで画面に出た 8桁のコードをメモし、PC 側のブラウザで https://github.com/login/device を開いてコードを入力します。

あとは STEP 6〜9 と同じコマンド（git add → git commit → git push）を仮想マシンの中で実行します。

ブラウザでの確認：仮想マシンの中に画面（デスクトップ）がある場合は、次のコマンドで開けます（xdg-open は Linux 共通の「いつものアプリで開く」コマンドです）。

cd /vagrant/ch03/03-18
xdg-open index.html

画面が無い仮想マシン（文字だけの画面）では開けないので、PC 側で共有フォルダの中のファイルを開きます。

# PC 側のターミナルで
cd ~/vagrant/ch03/03-18
open index.html

やり方3：VS Code から仮想マシンに接続する（Remote - SSH）

VS Code の画面のまま、仮想マシンの中のファイルを編集し、VS Code のターミナルも仮想マシンの中で動かす方法です。

  1. VS Code に拡張機能 「Remote - SSH」（Microsoft 製）を入れる
  2. PC 側のターミナルで、接続情報を SSH の設定に追加する（最初の1回だけ） 
    cd ~/vagrant              # Vagrantfile がある場所
vagrant up
vagrant ssh-config --host vagrant >> ~/.ssh/config
  3. VS Code でコマンドパレット（Ctrl+Shift+P）→ Remote-SSH: Connect to Host → vagrant を選ぶ
  4. 新しいウィンドウが開いたら「フォルダーを開く」→ /vagrant/ch03
  5. 左下に SSH: vagrant と出ていれば接続できています。ターミナルも仮想マシンの中なので、Git の準備は「やり方2」と同じく仮想マシン側で必要です

⚠ 親のフォルダがすでに Git につながっていると失敗する

すでに Git につながっているフォルダ（例：webex1）の中に ch03 を作ると、うまくいきません。Vagrant のフォルダや今までの授業のフォルダが Git で管理されている場合に起きます。

webex1/          ← すでに Git につながっている（.git がある）
├── .git/
├── Vagrantfile
└── ch03/        ← ✕ この中で git init して GitHub に上げようとすると失敗する
    └── 03-18/

Git は、今いるフォルダに .git が無いと親のフォルダをさかのぼって探しに行きます。そのため、次のどちらかの状態になります。

やったこと何が起きるか
ch03 で git init せずに git add / commit / pushGit の操作が親の webex1 に対して行われる。git status に関係ないファイルがたくさん出る、git remote add で remote origin already exists と言われる、git push すると親の別のリポジトリに送られてしまう
ch03 で git init したGit の中に Git がある「入れ子」の状態になる。親の webex1 側で warning: adding embedded git repository と出たり、GitHub 上で ch03 が中身の見えない空のフォルダ（矢印つきのアイコン）として表示されたりする

自分のフォルダが大丈夫か確認する方法

ch03 フォルダの中で次を実行します。

git rev-parse --show-toplevel   # 今いる場所が、どのフォルダの Git に入っているかを表示
git remote -v                   # 送り先の GitHub の URL を表示
結果判定
fatal: not a git repository（まだ git init 前）◯ 親は Git につながっていない。このまま STEP 7 の git init へ進んでOK
/home/ユーザー名/ch03 のように ch03 で終わるパス◯ ch03 が独立したリポジトリになっている
/home/ユーザー名/webex1 のように親のフォルダが出る✕ 親の Git に入っている。下の方法で直す

直し方

ch03 をGit につながっていない場所へ移動します（STEP 1 のとおりホームフォルダの直下が安全です）。

mv ~/webex1/ch03 ~/ch03   # webex1 の外へ移動（場所は自分の環境に合わせる）
cd ~/ch03
git rev-parse --show-toplevel   # まだ git init 前なら「not a git repository」と出れば OK

親のフォルダの .git を消して直そうとしないでください。今までの授業の履歴や、親が GitHub に上げていた内容とのつながりがすべて消えます。消すのではなく、ch03 の方を外に出すのが正解です。
なお Vagrant の中から作業したい場合も、共有フォルダ（Vagrantfile がある場所）自体が Git につながっていないかを、先に上のコマンドで確認してください。

Vagrant を使う時の注意

  • Git を実行する場所はどちらか片方に決める（PC 側か仮想マシン側か）。名前の登録やログインは場所ごとに別々なので、混ぜると「片方ではログインできているのに、もう片方では失敗する」ことになります
  • 作業が終わったら仮想マシンを止める：vagrant halt
  • 共有フォルダの外（仮想マシンの中だけにあるフォルダ）に置いたファイルは PC 側からは見えません。課題は必ず /vagrant の中に置きましょう
